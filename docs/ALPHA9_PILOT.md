# Haypile · 冬藏 Alpha.9 种子测试

这轮测试验证现有流程是否真的有用，不测试新功能。目标是邀请 6–8 人，完成 4
场；3 场且同时包含 AI 编程工具用户和设计/内容创作者，才构成最低有效样本。

## 隐私边界

- 请使用可公开或可丢弃的测试素材，不要使用客户文件、密钥或私人聊天内容。
- 不提交完整日志、本地绝对路径、素材文件名、网址参数、哈希或账号信息。
- 原始访谈笔记保持私密；GitHub 只记录匿名结论和可复现缺陷。
- Alpha 版本不能成为重要素材的唯一备份。

## 15 分钟独立任务

测试者先独立操作。观察者不主动提示，只记录卡住的位置和必要的干预。

1. 下载适合当前系统的 Alpha.9，完成解压、启动和首次打开。
2. 导入一张图片、一个 GIF 和一段音频，再重复导入其中一个文件。
3. 找到刚导入的素材，确认待处理项的用途，并观察重复或不支持文件的反馈。
4. 关闭并重新启动 Haypile，确认素材仍然存在。
5. 复制最新批次 handoff。

AI 编程工具用户继续：

6. 从 Agent 页复制 MCP 配置，让 Codex 或同类工具读取最新批次中的一项素材。

设计或内容创作者继续：

6. 找回刚导入的目标素材，并说明它是否适合自己一个真实、可重复的工作场景。

## 15 分钟访谈

- 哪一步最不确定？为什么？
- 在没有提示时，你认为“确认用途”和“handoff”分别会做什么？
- 哪一步需要观察者干预？
- 你会在一周内再次使用它吗？会用在哪件真实工作上？
- 现有 handoff 是否足够，还是必须把素材直接写入项目？

观察者私下记录：匿名编号、用户类型、平台、完成时间、干预次数、停止点、误解、
再次使用意愿，以及是否明确需要真实项目写入。不要把原始记录提交到本仓库。

## 阶段判定

- 数据丢失、越界访问或隐私问题：立即停止分发。
- 两名用户在同一核心步骤受阻：下一版本只修该阻塞。
- Agent 用户成功而创作者无法形成独立价值：定位收窄为面向 Agent 的本地素材入口。
- 两类用户都没有再次使用意愿：暂停功能开发，重新验证问题。
- 至少两名用户独立提出真实项目写入、且 handoff 无法完成任务：另开设计阶段；
  一人提出则继续冻结，无人提出则下一阶段从主线删除实验实现。
