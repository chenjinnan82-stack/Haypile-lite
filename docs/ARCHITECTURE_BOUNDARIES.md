# 模块边界与解耦验收

2026-10-14：完成本轮耦合审查识别的问题。目标是明确数据修改和后台任务的所有者，保持既有操作流程；不是消除所有模块调用，也不按文件行数拆分项目。

## 依赖方向

- 备份服务可以复用入库服务重建暂存索引；入库启动只调用独立的存储事务恢复，不加载备份服务。
- `storage_transactions.py` 管理快照锁、恢复记录、回退和持久化重命名，只依赖底层文件锁。
- `StorageRuntimeDB` 管理 SQL、恢复后的路径/最近顺序和 WAL 刷盘。备份模块不直接执行 SQL。
- GUI 调用服务层；服务层不导入 GUI 或 Qt。后端目录创建在应用生命周期启动阶段执行，导入后端模块本身不创建素材库。

## 查询与修改

- 素材查询通过 `ThemeRegistry.read_theme_contract` 在内存中兼容旧主题，不写回、不隔离文件；读取失败通过 `theme_read_errors` 报告。
- `ensure_theme_contract` 和 `upsert_image_asset` 是明确的创建、修复或修改入口。损坏主题保留在原处，用户重新确认用途时才隔离损坏记录并写入新内容；不会因为打开素材列表就发生修复。
- 最新批次、具体批次及最近素材读取不会调用数据库初始化/迁移；批次查询使用只读连接，未建立数据库时返回空结果。初始化和迁移仍由入库/启动流程负责。SQLite 自身可能使用 WAL/SHM 协调文件，这不等于执行业务写入。
- 音频用途更新与字体更新一样使用入库锁，防止备份取得主题与来源记录不一致的快照。
- GUI 通过公开的 `asset_path` 解析素材路径；路径边界和符号链接检查保留在服务内。

## 桌面协调

- C 环通过几何回调定位，通过 Qt 信号请求动作；原生输入读取在 `desktop_input.py`，无需素材卡片或草堆业务对象。
- 素材卡片通过信号请求收纳、取消、重试、清理候选和刷新提示，通过服务工厂读取素材。它仍读取草堆公开的操作状态和配置，这是应用协调依赖。
- 素材面板和卡片各自管理预览任务与退出状态。草堆只等待公开的 `shutdown_pending`，不逐个清理其他窗口的线程。
- 单项和批量 AI 整理结果先暂存，收到 QThread 的 `finished` 后才释放线程和更新界面；完成通知尚未处理时仍禁止重试，退出时禁止启动新任务。只接受当前任务的信号，旧任务延迟通知不会清理新任务。
- 进度显示、注意提示和卡片消息通过窗口方法更新；共享字体标签不再借用其他窗口的私有方法。
- Agent 配方与素材 handoff 构造归入已有 `handoff.py`，草堆无需调用素材面板生成数据。

保留 Qt 父子生命周期、应用入口对窗口与服务的组装，以及服务对配置/存储的调用。`app_gui.py` 仍较大；仅把代码移到更多文件不会进一步改变这些边界，因此没有新增通用控制器框架、接口层或依赖注入容器。
